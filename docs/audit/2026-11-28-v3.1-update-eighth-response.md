## Experiment results (gates 1, 4 and 5)

A first run of three stand-alone experiments on 28 November 2026: on the Windows
development machine and on the x86_64 Android 9 emulator. An emulator is not a real
phone; arm64 was built but not run. Each folder has pinned versions, saved results and a
README. This is feasibility work, not an audit.

- **Gate 1, `experiments/sqlcipher-store/`.** Raw key, wrong-key refusal, changed-page
  and integrity checks, WAL, FULL and the commit hook work, also on the emulator. 56 of
  56 estimate runs passed with about 2x headroom, on seven cases only; history rows,
  sender-key state, group state, retirement and a full session plus history are still to
  do.
- **Gate 4, `experiments/noise-pairing/`.** Full original and resume exchanges, wrong
  `psk` or prologue, truncated and flipped messages and the 65,535-byte maximum all
  behave as written (12 tests).
- **Gate 5, first part, `experiments/stream-attachments/`.** The size table (0 to
  262,081 bytes), final-flag checks and manifest equations pass (15 tests), and both
  STREAM crates give identical bytes.

Decisions written into the proposals (planner, 28 November 2026):

- **Crypto provider:** LibTomCrypt 1.18.2, as built in the experiment; speed unmeasured,
  for gate 6; gate 1 results apply to that provider (local storage §1).
- **STREAM crates:** the support built into the pinned `chacha20poly1305` 0.10.1, not
  the `aead-stream` 0.6 crate, which needs 0.11; the old "same family" wording is
  corrected (attachments §1, gate 5).
- **Gate 1 measurement:** the hook never fires for a rolled-back transaction, so "the
  hook was called" covers committed ones only; peak space uses file lengths (a
  rolled-back transaction with cache spill left 251 frames, about 1 MB); installing the
  hook replaces SQLite's automatic checkpoint, so the app runs its own; the build uses
  no temporary files; estimates use 4,016 usable bytes of each 4,096-byte page (local
  storage §5).
- **Pairing:** the 48-byte rule is Yap's own length check before `snow`, which accepts a
  valid 49-byte message; the prologue uses the decoded raw QR payload bytes; one
  prologue vector is added; and a wrong `psk` or prologue shows "Couldn't connect. Check
  you both scanned the right code" after 30 seconds (pairing §2, test plan).

Also found by the same session, outside the proposals: five clean-ups' instrumented
tests, run on the emulator, gave 8 passed, 5 failed, 1 skipped. Four failures look for
text the clean-ups removed (stale tests) and one, the pairing page, timed out for an
uninvestigated reason with no baseline run. Nothing was changed.
